# T23 다전공 지정 과목 · 빅뱅에서문명까지 배제 계획

> 상태: 승인·구현 완료 (2026-11-01). 사용자 결정을 2026 교육과정 원문과 시드에 맞춰 정리했다.

## 1. 사용자 결정

1. 다전공 과목이 책자에 정해진 학과는 과목까지 적용한다.
2. "필수 교과목" 문구만 있는 학과(식물·환경신소재, 식품, 유전, 한방, 융합바이오)는 학점만 있는 학과와 똑같이 현상 유지한다.
3. 빅뱅에서문명까지를 전공기초로 대체하는 학과는 그 과목을 아예 뺀다. 대체 과목이 전공기초라 안 들을 수 없다는 판단이다.

### 빠진 과목을 세는 방법

- 컴공 전공필수 4과목: **전공선택으로 옮긴다.** 표2가 "다전공 전공필수에 포함되지 않은 단일전공의 전공필수/전공선택"을 전공선택으로 인정한다.
- 나머지 25과목: **그 전공의 다전공 학점에 넣지 않는다.** 해당 표의 전공선택 목록에 없다. 제1전공 쪽 기록은 `기타`로 옮긴다.
- 두 전공에 같은 과목이 있으면 전공별로 따로 판단한다. 컴공 + 소프트웨어융합이면 미분방정식은 컴공에서 빠져도 소프트웨어융합 전공기초로 남는다.

### 바뀌는 곳

- 남은 수강 과목: 빠진 과목을 보여 주지 않는다. 컴공 4과목은 전공선택으로 표시한다.
- 이수현황·홈·마이페이지(제1전공), 다전공 카드(제2전공): 위 기준으로 학점을 센다.
- 전공필수 학점은 지정 과목으로만 채워지므로 지정 과목을 빠뜨리면 `graduatable` 이 false 가 된다. 별도의 "빠진 과목" 판정은 만들지 않는다.

## 3. 빅뱅에서문명까지 배제

근거: 교육과정 p22 제4조①, p40 별표4(2024학번 이후), p41(2019~2023학번). 제1전공의 `course_unit` 기준이고, DB가 다루는 2020~2026학번 모두 적용한다.

대상 26개 단위:

- 공과대학: 기계공학부, 산업경영공학과, 원자력공학과, 화학공학과, 신소재공학과, 사회기반시스템공학과, 건축공학과, 환경학전공, 환경공학전공, 건축학과
- 응용과학대학: 응용수학과, 응용물리학과, 응용화학과, 우주과학과
- 생명과학대학: 식물·환경신소재공학과, 식품생명공학과, 원예생명공학과, 유전생명학과, 한방생명공학과, 스마트팜과학과, 융합바이오·신소재공학과
- 전자정보대학: 전자공학부 전자공학과, 생체의공학과
- 소프트웨어융합대학: 컴퓨터공학부 컴퓨터공학과, 컴퓨터공학부 인공지능학과, 소프트웨어융합학과

반도체공학과는 별표4에 없어서 대상이 아니다.

대상 학과의 계산:

- 필수교양 체크리스트와 남은 수강 과목에서 빅뱅에서문명까지를 뺀다.
- 필수교양 요구 17 → 14, 교양 합계 29 → 26, `기타` 요구 +3. 졸업 총학점은 그대로다(별표4: 대체 학점은 영역에는 반영되고 졸업학점에는 중복 인정되지 않음).
- 이미 들은 학생은 필수교양이 17/14 로 보인다. 학점 합계는 그대로 맞다.

## 4. 파일

코드 (신규 파일·Flyway·DB 변경·의존성 추가 없음):

- `academic/service/DoubleMajorCalculation.java`: 2장 과목표 상수, 학과·과목별 이수구분 판단, 제2전공 합산에 적용
- `academic/service/AcademicProgressService.java`: 3장 대상 상수와 계산, 제1전공 합산에 2장 적용
- `academic/service/RemainingCourseService.java`: 남은 과목 필터와 컴공 4과목 표시

테스트: `AcademicProgressServiceTest`, `RemainingCourseServiceTest` 에 추가. 다전공 계산 테스트가 `AcademicProgressServiceTest` 에 있어 `DoubleMajorServiceTest` 는 그대로 둔다.

문서: `BACKEND_SPEC.md` 5장 9·12번과 9장 29, `FRONTEND_GUIDE.md`, `PROGRESS.md`, 이 계획서.

과목표를 테이블이 아니라 상수로 두는 이유: `STARTUP_SEMINAR_UNITS` 와 같은 방식이고, 시연 당일 DB 마이그레이션이 필요 없다. 학과가 늘면 `minor_designated_courses` 와 같은 테이블로 옮긴다.

## 5. 작업 방식

- 사용자 작업 폴더를 건드리지 않도록 `origin/master` 에서 별도 worktree 와 브랜치 `feat/double-major-courses` 를 만든다.
- 검증: 컴파일, 전체 테스트, 8081 실서버(컴공 + 시디 등 2026학번 계정). 8080·3000 은 건드리지 않는다.
- 반영은 사용자가 푸시·머지하고 8080 을 다시 켜야 화면에 나타난다.

## 6. 한계

- 소프트웨어융합 트랙필수: 사용자의 트랙을 저장하지 않아 적용하지 않는다.
- 우주과학 전공필수: 표에 10과목이 있고 4과목을 자유롭게 고르므로 바뀌지 않는다.
- 대체 인정(객체지향프로그래밍및실습 → 객체지향프로그래밍, 타학과 표3)은 판정하지 않는다.
- 생체의공·응용수학을 제1전공으로 다전공하면 빅뱅 대체 과목(물리학1, 미분적분학·화학및실험1)이 전공기초에서 빠져 안 들을 수 있다. 사용자 결정대로 이 경우에도 빅뱅을 뺀다.
- 컴공 단일전공 전공필수 시드 42 와 책자 39 의 차이는 별도 작업이다. 다전공 값(27)에는 영향이 없다.
